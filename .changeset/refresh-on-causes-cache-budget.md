The Tree now refreshes when something changed, not on a timer, and keeps the GitHub budget safe. It reads the tracker when you show the view, when the window gains focus, when a file under `.scratch` changes on a local tracker (one second after the last change), and when you press Refresh. On a GitHub tracker those automatic reads wait at least 60 seconds after the last good one; the Refresh button always reads, and joins a read that is already running. Only one read runs at a time, with at most one waiting behind it. VS Code's progress bar shows while it runs. The last good read is kept per repo and shown the moment the window opens, then swapped for the fresh one. When GitHub has fewer than 1,000 points left the automatic reads pause until the limit resets and the repo row says "paused until HH:MM"; at 0 they stop and Refresh says "rate-limited until HH:MM" without calling GitHub. After a secondary limit the automatic reads back off for the wait GitHub asks for, or 60 seconds, doubling each time it repeats. A failed read never retries by itself, and the repo row's age turns to a warning, with the reason, when the last read failed or is more than 5 minutes old.
