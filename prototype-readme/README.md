## The recommendations

### First screen

- **Repository README: A, the banner first.** The 3:1 banner JPG, centred, names the project and says "A VS Code cockpit for `mattpocock/skills`" before a word is read. Under it, two badges, then the opening paragraph and the unofficial line left-aligned, then the trailer, then the real window, then the problem. B opens on a video, which GitHub shows as its first frame until it is played, so the name comes only from the H1; C's centred Seal and loop make a smaller first screen that repeats the listing.
- **Listing README: A, the window first.** The Marketplace header already shows the icon, the name and the description, so the listing opens on the opening paragraph and the window: the map, its frontier and live statuses at a glance. The ▶ loop goes in the quick start, at the step it shows.
- **Alignment.** Images and the sign-off centred; prose left-aligned everywhere.
- **Badges.** Two on the repository README: the Marketplace version and the licence, in Indigo. shields.io has retired its Marketplace badges, so the version comes from vsmarketplacebadges.dev. No build, install-count or rating badges: they say nothing about the Cockpit and an install count of a new extension undersells it. None on the listing, as [#115](https://github.com/dbarjs/hero-synergy/issues/115) found.

### The repository README

Banner, badges, opening paragraph, unofficial line, trailer, the window, the problem, then the trailer's four product beats as headings over real shots: "See the frontier", "One click, one named session", "Live status for every session", "Close one, unblock the rest". Then Install, How it works with a Mermaid diagram, Built with its own maps, Packages, Developing, the tagline as sign-off, Credits and Licence.

### The listing README

Opening paragraph, unofficial line, the window, then Requirements, Quick start (install the skills, Setup, Chart a map, ▶ on a frontier ticket, with the loop), The Cockpit (the Tree, the Focus pane, the Detail), Live status and the badge, Settings, Commands, Conventions, Troubleshooting (the Health row, drift, the output channel) and Links. No banner, no tagline, no badges.

### The trailer beside the Cockpit

**Cut the trailer instead of captioning it.** The README video keeps the trailer's problem beats and the Seal (0 to 9.9 s) and ends on its outro (24 to 30 s) with the "VS Code extension + CLI" footer painted out. The stylized board, and the typed command without its `#<number>`, fall out with the 14 seconds between. All three differences from the product go; no caption is needed. The trailer's four product beats become the repository README's headings, each over a real shot.

The cut is 15.5 s of 1920 × 1080 at 60 fps with stereo sound, 9.2 MB: under the 10 MB upload cap. It plays only on GitHub, uploaded by [#120](https://github.com/dbarjs/hero-synergy/issues/120). The listing has no video.

### Social card

**`card-outro.png`**: the Seal, the name and the tagline, cut above the "+ CLI" footer, 1280 × 640, 776 KB. It is the card [#117](https://github.com/dbarjs/hero-synergy/issues/117) described: a thumbnail carries the eight-word tagline, and the link preview's text already shows the About line.

### `--no-gitHubIssueLinking`

The listing's alt text names tickets as `#5`, `#8`, `#10`; vsce would turn each into a link to this repository's issues. The `package` script on this branch passes `--no-gitHubIssueLinking`.
